# Grid tower placement audit

Audited 2026-10-24 before implementation.

## Existing construction architecture

`apps/units/services.py:ConstructionService.build_tower` authenticates ownership, locks Match then Team, checks ActionPolicy (phase, unlock, coins, active tower cap), debits EconomyService, creates GameEntity and GameAction and records TOWER_BUILT. Match events broadcast through transaction.on_commit. Match-wide locking also serializes combat ticks and construction. Six is independently configured as `max_towers_per_team`; retain it.

No `build_slot_id` field exists. Fixed slots are node IDs (`node_tower_tN_slot1..6`), generated by `combat/map.py`, validated by `units/map.py`, returned in team state, and consumed by BattlePage, actionAvailability, BattleScene markers, terrain foundations, graph range and combat targeting. Existing entities store current_node_id and simulation_state JSON. Realtime snapshot and delta serializers already support physical world_position for troops. Dynamic towers must carry that position through the public field whitelist, REST and TOWER_BUILT reducer. No new graph nodes should mutate the cached shared map.

## Damage

`units/seeds.py` Cannon Tower (stationary TOWER) is HP 150, damage 30, range 2, cost 40. Artillery is a separate UNIT (damage 40). `combat/balance.py:attack_damage` applies level damage once; `units/upgrades.py:effective_stats` supplies catalog and inspection values. Level modifiers are 1, 1.10, 1.20, 1.35. Existing database catalog rows require a data migration, not only a seed edit.

## Modal root cause

`TeamUpgradeModal.tsx` mounts one persistent dialog; category buttons have stable code keys. The panel CSS has only max-height:92dvh and overflow:auto, so actual height follows content. Mobile uses one stat column. Categories filter differing stats, errors/confirmation add content, and Lv.4 removes the next preview and purchase content. Flex overlay recenters after every content-height change. Header, tabs and action currently share the scrolling panel. EntityIllustration already reserves image dimensions and loading placeholders; image fetch is not the primary cause. Keep its fixed preview container and separate header/navigation, scrolling article, fixed footer.

## Geometry and compatibility concerns

Arena layouts 3–5 project graph coordinates by rotation -135 degrees, x scale 1.5, y scale .86, plus arena center and y+60. Layout 5 protects existing artwork via BuildGeometry. Terrain paints curved roads, bridges over a procedural river, staging patches and decorative vegetation. Navigation uses straight graph edges and staging_bounds; protect both straight and painted roads and the full staging bounds. Bases use asymmetric artwork/input bounds. There is no territory model: derive exclusive radial sectors from the original graph coordinates. Grid must use server-authored projected square cells and serialized buildable masks; camera padding is not buildable terrain.

All tower sprites currently share 94px artwork and a banner, with conservative bounds (-54,-90,54,25); reserve a common multi-cell footprint rather than guessing single-cell sizes. Existing non-destroyed towers reserve their physical artwork without relocation. Destroyed structures currently release their slots; preserve that policy. Missing placement version means legacy slot construction; new-room configuration must opt into grid construction without retroactively changing stored matches.
